# 上线与离线诊断

程序通过 HTTP `/api/info` 发现设备。旧逻辑会把一次超时或扫描漏报直接判为离线，并且对备用端口设备错误地使用本机端口保活；多网卡公告地址、手动添加设备未进入保活列表、前端独立的 25 秒超时判定也会造成状态反复变化。

修复后使用实际连接成功的 IP 和端口保活，连续 3 次失败才判离线，离线设备继续接受探测以便恢复。扫描与保活独立调度，扫描漏报不直接判离线；手动添加和收到消息发现的设备也加入保活，桌面前端使用后端状态。自动扫描覆盖当前网卡的 `/24` 网段和 `57088`、本机端口、`7890`，其他网段或其他自定义端口需要手动输入 IP 与端口添加。端口修改保存后，重启程序才会改变监听端口。

## 采集现场

运行修改后的程序，在项目根目录的 PowerShell 中执行，将示例 IP 改成另一台设备的实际 IPv4 地址：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\diagnose-network.ps1 -TargetIp 192.168.1.20
```

默认连续采样 12 次，间隔 5 秒，同时检查本机 `127.0.0.1` 与指定对端。自定义端口可添加 `-Port 58000`；仅检查本机可省略 `-TargetIp`。脚本不扫描全网，也不修改网络设置。每次 HTTP 请求最多等待 2.5 秒，绕过代理，以匹配程序保活环境。

输出默认保存在 `[用户文档]\LAN Drop\logs\diagnostics.txt`，每次覆盖，不在项目根目录生成报告。包含网卡、网络类型、防火墙状态、监听进程、请求耗时与简短错误，以及应用日志最后 30 行。建议在两台设备各执行一次，按需备份问题发生时的报告。

程序日志路径：`[用户文档]\LAN Drop\logs\app.log`。只记录启动与监听、设备上下线、更新与退出等关键事件，以及警告和错误。消息正文、头像、周期扫描、成功发送消息、离线后的重复保活失败均不写入。设备离线时一次性记录地址、连续失败次数和原因，恢复时记录上线。

时间使用本地时间并附时区，例如 `2026-10-08 14:31:17.243+08:00`。单个日志文件达到约 2 MiB 后轮换，仅保留 `app.log` 和 `app.previous.log`。旧版的 `network-diagnostics.log` 不再写入，可在退出旧版程序后自行归档或删除。

## 判断原因

- 本机回环失败：查看 `[监听失败]` 和端口对应进程，确认程序启动与实际端口，排查端口占用。
- 本机回环成功，对端持续失败：在对端检查本机回环；如果两边本机均成功，进一步核查实际 IP、网络隔离与防火墙入站规则。
- 请求间歇超时：查看采样耗时和 `[设备离线]` 中的错误原因；一次失败不会立即离线。
- HTTP 状态或 JSON 错误：目标端口可能是其他服务，检查监听进程与实际端口。
- 公告 IP 或端口不同：可能为旧版程序、多网卡或配置尚未重启生效；新版使用连接成功的地址通信。
- HTTP 均成功但列表仍离线：对照日志中设备 ID、`[设备上线]` 与前端控制台 `[设备离线]`，确认两端运行的是修改后的版本。
